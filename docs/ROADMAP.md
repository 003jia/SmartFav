# SmartFav 更新计划

这份路线图用于记录 SmartFav 接下来的功能方向。版本号是建议顺序，不代表固定发布日期；每一版都以稳定、可恢复和不破坏已有收藏为前提。

## 产品原则

- 本地分类始终可独立使用，没有 API Key 也能完成收藏、分类和整理。
- AI 只负责可选建议，不接管基础流程，不在未确认时写入规则。
- 用户修正分类后，SmartFav 可以学习，但必须说明将学习什么并允许拒绝、查看、撤销。
- 浏览器书签同步必须可重复执行、避免循环操作，并保留恢复手段。
- 升级不能丢失已有收藏、分类、关键词、排序和设置。

## 1.14.0：分类学习第一版

已完成：

- SmartFav 内手动跨分类移动书签后，询问是否“记住这次分类”。
- 只有用户确认后才写入 `domain:example.com` 域名规则。
- 取消不会修改关键词规则，也不会触发已有收藏重新分类。
- 学习规则直接显示在对应分类关键词中，可编辑或删除。
- 同一域名已有旧规则时先提示冲突，确认后移动规则而不是保留两个归属。
- 域名规则同时用于后续插件收藏、浏览器星标自动获取和浏览器收藏夹整理。
- 当前网页分类增加“把握高 / 中 / 低”与实际匹配依据。

## 1.14.1：当前网页分类修正

已完成：

- 当前网页手动修改推荐分类后，显示“同时记住这个网站的分类”。
- 普通分类默认勾选学习；“其他”默认不勾选，避免把临时归类长期固定。
- 收藏与学习规则在同一次本地存储写入中提交，避免只成功一半。
- 保存后可立即撤销学习；撤销恢复原关键词规则，但保留刚收藏网页的手动分类。
- 同一域名已有旧规则时，学习选项会说明规则将从哪个分类移动到哪里。
- 已验证中文、英文、明亮、暗色、保存、撤销及收藏保留。

## 1.14.2：AI 文件夹关键词提炼

已完成：

- 在“分类文件夹”中增加“AI 分析并填入”，复用现有 AI 服务与 API 配置。
- 每个非空文件夹最多选取 12 条代表性收藏，只发送标题、域名和不含查询参数的网址路径。
- 同时发送文件夹名和已有普通关键词，要求模型只返回现有文件夹的候选关键词。
- 文件夹按 5 个一批处理；任一批失败时不修改匹配字段，避免只完成一半。
- 过滤未知分类、完整 URL、`domain:` 规则和重复项，并在保留原规则的前提下合并。
- 建议先显示在关键词输入框中并标记新增数量；只有点击“保存并重新分类”才会写入设置。
- 已验证中英文、明暗模式、360px、320px、成功填入、未保存离开和未配置 AI 提示。

## 1.14.3：状态一致性与发布加固

已完成：

- 收藏、浏览器事件回流、回收站、重新分类、设置和排序写入统一进入后台状态事务队列。
- 设置保存改为字段补丁合并，避免不同操作用旧快照覆盖整份设置。
- 浏览器活动提示按活动 ID 消费，旧提示不会清除刚到达的新提示。
- storage 读取与写入均检查浏览器错误，失败时保持原数据并返回明确错误。
- 新增跨入口并发、浏览器删除回流、设置合并、排序合并和读取故障测试。
- 发布包增加源码一致性验证，避免再次出现 ZIP 可解压但内容仍是旧版本。

## 1.14.4：后台分层重构

已完成：

- 抽出 `state-store.js`，集中状态归一化、读取、合并和浏览器存储错误处理。
- 抽出 `bookmark-guard.js`，由单一工厂实例维护内部书签标记、事件队列与布局事务锁。
- 抽出 `favorites-service.js`，收藏、同步、回收站、整理和备份继续共享同一事务边界。
- `background.js` 收敛为 248 行，只保留生命周期、三类浏览器书签事件监听与 21 条消息路由。
- 测试夹具执行后台真实 `importScripts` 链，并覆盖锁串行、失败恢复、worker 重启标记恢复及跨入口并发。
- 存储结构、消息协议、首次安装默认词表和本地优先行为保持兼容。

## 1.15.0：分类学习闭环

下一版优先完成：

1. 浏览器中手动跨文件夹移动书签后，记录为待确认的学习建议；下次打开 SmartFav 时统一确认。
2. 增加“已学习规则”管理区，展示域名、目标分类、创建时间和来源。
3. 支持暂停、删除和长期撤销学习，不需要手动查找关键词输入框。
4. 用户可选择“只影响以后”或“预览并重新检查已有收藏”，默认仍为只影响以后。
5. 分类依据继续使用可解释的高、中、低把握度，不伪造精确概率。

验收标准：

- 未点击确认时，设置和分类结果不能发生隐式变化。
- 撤销后恢复原规则；存在旧规则冲突时也能恢复原归属。
- 同一操作重复触发不会生成重复规则或重复学习记录。
- 同步开启和关闭两种状态都能正确工作。
- 中英文、明暗模式和紧凑弹窗均可完成确认与撤销。

## 1.16.x：完整数据备份

在现有“浏览器整理前布局备份”之外，增加 SmartFav 自身数据备份：

- 导出收藏、分类、关键词、学习规则、排序、设置和最近删除。
- 导入前展示版本、数量、冲突和预计变化。
- 支持“合并导入”与“完整恢复”两种方式。
- 导入失败时保持原数据不变，并提供可读错误说明。
- 备份文件增加格式版本和完整性校验，方便跨 Chrome、Edge 或设备迁移。

## 1.17.x：查找与批量整理

- 按标题、网址、域名、分类和关键词搜索。
- 识别同网址和规范化后相同的网址，提供合并预览。
- 支持多选移动、批量删除、批量恢复和批量重新分类。
- 可选检测失效网址，但不自动删除，避免网络异常造成误判。

## 后续：可选 AI 与语义建议

- 1.14.2 已交付第一版文件夹候选关键词建议，并坚持由用户检查后保存。
- 后续可增加建议历史、关键词冲突对比、单文件夹重试和更细的语义匹配。
- AI 可以继续建议新分类或学习规则，但必须由用户确认。
- 优先复用现有 OpenAI 兼容、Anthropic 兼容和本地 Ollama 接口。
- 仅发送用户明确选择的内容，并在调用前说明会发送哪些数据。
- 无 API Key、接口不可用或额度不足时，继续使用本地域名、关键词和向量匹配。

## 每版发布检查

- 运行全部 JavaScript 语法检查和 `node tests/verify-extension.js`。
- 验证 Chrome 与 Edge 的新装、覆盖升级和重新加载。
- 验证中文、英文、明亮、暗色及紧凑宽度。
- 验证同步开启、同步关闭、重复书签和浏览器事件回流。
- 检查 ZIP 根目录包含 `manifest.json`，使用 `unzip -t` 验证压缩结构，并运行 `tests/verify-release-package.js` 对比源码与包内容。
- 更新 README、版本说明和安装包链接后再发布。

## 发布包策略

- 1.14.0 已提供的 SHA-256 文件保留为历史记录。
- 从 1.14.1 开始只发布扩展 ZIP，不再单独生成 `.sha256` 文件。
- GitHub HTTPS 下载和 Chrome / Edge 商店发布已能满足当前用户的完整性保护需求。
- 如果以后增加第三方下载镜像、企业离线分发或自动更新服务，再重新评估校验文件或数字签名。
